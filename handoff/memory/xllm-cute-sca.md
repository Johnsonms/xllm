**Design (V, S <= 256):** ScaFwd per (b, h, chunk, 128-row q tile): q tile resident in smem, 64-key K/V blocks in 2-stage TMA rings, S in TMEM (2 x 64 cols), P bf16 stored into TMEM as the A operand of the PV MMA, O 256 cols; 4 softmax warps (thread = row), lazy O rescale (threshold 8 in log2 units). Mask = per-row key range [kmin(row), row] from `segment_starts`; blocks outside skipped. Saves y + lse2 (log2 domain, scale folded). Generic backward = 3 kernels: ScaBwdDv, ScaBwdDk (V tile in TMEM as A of dP^T, Q block bytes reused as K-major and MN-major B), ScaBwdDq (mirror, dO in TMEM). For V > 256: v slabs + `load_dp` variants reading fp32 dP from cuBLAS.

**TMEM-A rewrites (2026-10-24):** the worst case (no segment boundaries) had the tensor pipe 30-40% busy: 512 TMEM cols -> 1 CTA/SM so handshake latencies are exposed, and N=64 GEMMs with A and B in smem run at ~55% of peak (smem operand bandwidth; proven with an MMA-only mode SCA_DBG=3). Backward (S + V <= 256, gekko-4B): ScaBwdDkDv (dK+dV in one pass: K, V in TMEM as A operands, P^T over the S^T columns, S^T/dP^T double-buffered 32-query blocks, 8 compute warps in 2 groups alternating blocks, MMA order dV_j, dK_{j-1}, dP^T_{j+1}, S^T_{j+2}, raw mbarriers) and ScaBwdDqT (Q, dO in TMEM, 64-key blocks): per layer dK+dV 2546 -> 1071 us, dQ 1042 -> 710, bwd 3627 -> 1824 (floors 753/562); 1-GPU step 474 -> 424 ms, 8-GPU grp=4 485 -> 428. Forward ScaFwdT (q in TMEM; 4B: 256 cols with KB=32 -> 2 CTAs/SM, needs `relinquish_alloc_permit` right after the allocation; S=256: KB=64 with P over S): 4B 668 -> 550 us per call, 0.9B 558 -> 540, 7.1B unchanged; step <= 1%. 4B forward is exp2 bound (238 us of MUFU per layer).

**7.1B dV via materialized P + cuBLAS (user: "把 7.1B 的 dV 用物化 P^T + cuBLAS 做一下"):** ScaPmat writes P bf16 chunk-major [C queries x 2C keys] per (c, b, h) incl. the zeros (no memset), dV_c = bmm(P_c[:, C:]^T, dO_c) + baddbmm_(P_{c+1}[:, :C]^T, dO_{c+1}) on the chunk-major dO, ChunkMajorUncopy back to [B, L, K, V]. 7.1B per layer no boundaries: dV 2.86 -> 1.47 ms, bwd 6.13 -> 4.92. The GEMM path cost is fixed, the v-slab kernel's shrinks with segments (2.86 x attended fraction): crossover ~0.5 -> `_use_pmat_dv` picks per call from qmax (one .item()); training batches with eos take the kernel path (7.1B step unchanged 939 ms). dK/dQ on the same path (commit 88b246b): fp32 dP GEMMs [queries x keys], ScaDsMat writes dS bf16 in P's layout, dQ/dK = two bmm per chunk on chunk-major K/Q copies: dK+dQ 1.8 -> 1.0 ms, bwd 6.13 -> 4.16 ms/layer (no boundaries); model loss/gnorm parity. Fusing dS into ScaPmat (register reads / early issue / cp.async staging) was always slower (1.2-1.5 vs 0.46+0.52 ms): strided per-thread fp32 dP reads are latency bound, and the 2-CTA/SM budget (<=168 regs, <=114 KB smem) leaves no room for deeper prefetch. Remaining: dense GEMMs over half-empty causal blocks (dP 1.2, dV 1.06 ms) - 2x2 sub-blocking would save ~25%.

**Perf (B200, 1 GPU, cute AWM+TSDN in both):** 0.9B (B2 L16384) step 1151 -> 590 -> 530 ms, peak mem 139 -> 40 GB. 4B (B1 L8192) step 967 -> 455 -> 424 ms. 7.1B (V=2048, B1 L16384) step 1050 -> 968 -> 939 ms, 98 -> 81 GB.

**DSL pitfalls learned:** (1) tcgen05.ld/st are warp-collective: per-thread `if` around them hangs -> `vote_any_sync`. (2) Use -inf for masked scores. (3) Never commit a producer stage nobody consumes / tail() on it. (4) TVM-FFI fake tensors are int32-sized: >2^31 elements need a 2-D fake + column-major `.t()` view; Int64 offsets in-kernel. (5) `consumer.clone()` to hold a stage across iterations. (6) TMEM pointer offsets work. (7) ptxas if-converts a dynamic `if` around ~160 selects: put masked/unmasked bodies in a `@cute.jit` helper with explicit args (closures captured in staged for/if are rejected) instantiated twice. (8) `tm.set(ACCUMULATE, dynamic)` in a jit helper leaks staged state -> rebuild the tiled MMA from the op inside, zero-init accumulators. (9) `cutlass.range_constexpr` only in jit/kernel functions. (10) An empty mbarrier with no first producer starts at parity 1. (11) ncu `--page source --print-source cuda,sass --csv` + CUTE_DSL_LINEINFO=1 shows per-line exec counts and `@P` predication (src_an.py). (12) 2 CTAs/SM with TMEM needs `relinquish_alloc_permit()` right after `allocate`. (13) N=32 MMAs cost 2x the issue of N=64: only worth it when it buys 2 CTAs/SM. (14) Same seed + different call order = different segment draws: compare old/new in one process. (15) A vector value (`.load()`) reused in two dynamic loops fails dominance: reload inside each loop.

Task (user, 2026-10-23 evening, after the step profile showed swift SCA at 58% of the 0.9B step): "去做 CuTe 的 sliding chunk attention kernel". File `xllm/modules/fused_ops/cute/sliding_chunk_attention.py`, wired as `sca_backend='cute'` in `xllm/modules/fused_ops/attention/sca.py` (falls back to swift with a warning for head dims > 256, prev chunk (CP), dropout), tests `tests/test_cute_sliding_chunk_attention.py` (19 tests). Branch cute-adaptive-working-memory (commits ab9065f, 4e36013, 459db31; 2026-10-24).

**Design (V, S <= 256):** ScaFwd per (b, h, chunk, 128-row q tile): q tile resident in smem, 64-key K/V blocks in 2-stage TMA rings, S in TMEM (2 x 64 cols), P bf16 stored into TMEM as the A operand of the PV MMA (as in the official CuTeDSL fmha example at /data/home/johnson/cutlass/examples/python/CuTeDSL/cute/blackwell/kernel/attention/fmha/), O 256 cols; 4 softmax warps (thread = row), lazy O rescale (threshold 8 in log2 units). Mask = per-row key range [kmin(row), row] from `segment_starts`; blocks outside skipped. Saves y + lse2 (log2 domain, scale folded). Generic backward = 3 kernels: ScaBwdDv (per key tile, loops heads of the kv group x 64-query blocks up to `query_limits`), ScaBwdDk (V tile in TMEM as A of dP^T = V dO^T, Q block bytes reused as K-major and MN-major B - verified identical SW128 layouts), ScaBwdDq (mirror, dO in TMEM). For V > 256: v slabs + `load_dp` variants reading fp32 dP from cuBLAS.

**Backward rewrite for S + V <= 256 (gekko-4B; user 2026-10-24: "去优化 SCA 反向的最坏情况"):** the worst case (no segment boundaries) was 3.6 ms/layer with the tensor pipe 30-40% busy. Causes: 512 TMEM cols -> 1 CTA/SM so handshake latencies are exposed; N=64 GEMMs with A and B in smem run at ~55% of peak (smem operand bandwidth; proven with an MMA-only mode SCA_DBG=3). Fix = ScaBwdDkDv (dK+dV in one pass: K, V in TMEM as A operands, P^T over the S^T columns, S^T/dP^T double-buffered 32-query blocks, 8 compute warps in 2 groups alternating blocks, MMA order dV_j, dK_{j-1}, dP^T_{j+1}, S^T_{j+2}, raw mbarriers, S^T stage freed by the dV commit) and ScaBwdDqT (Q, dO in TMEM, 64-key blocks). Per layer 4B: dK+dV 2546 -> 1071 us, dQ 1042 -> 710, bwd 3627 -> 1824 (floors 753/562); 1-GPU step 474 -> 424 ms (worst step 520 -> 458), 8-GPU grp=4 485 -> 428. S+V > 256 (0.9B/7.1B) unchanged (TMEM budget: 1.5(S+V)+4QB <= 512).

**Perf (B200, 1 GPU, cute AWM+TSDN in both):** 0.9B (B2 L16384) per layer fwd 0.83 ms / bwd 3.0 ms (swift ~12 / ~11); step 1151 -> 590 ms (530 after the create_on_gpu fix), peak mem 139 -> 40 GB. 4B (B1 L8192) step 967 -> 455 -> 424 ms. 7.1B (V=2048, B1 L16384): fwd 0.77 / bwd 3.4 ms per layer via V slabs + cuBLAS dP; step 1050 -> 968 ms, 98 -> 81 GB. Remaining 7.1B bwd cost: dV 2.8 ms (8 v-slab S^T recomputes; a materialized bf16 P^T + cuBLAS dV would save ~1.5 ms/layer), dP GEMM 1.2 ms.

**DSL pitfalls learned:** (1) tcgen05.ld/st are warp-collective: a per-thread `if` around the O rescale hung -> `vote_any_sync`. (2) Use -inf for masked scores. (3) Never commit a producer stage nobody consumes / tail() on it (hang). (4) TVM-FFI fake tensors are int32-sized: >2^31 elements need a 2-D fake + column-major `.t()` view; Int64 offsets in-kernel. (5) Holding a pipeline stage across iterations: `consumer.clone()` for a second state. (6) TMEM pointer offsets (`tmem_ptr + cols`, `recast_ptr(..., BFloat16)`) work. (7) ptxas if-converts a dynamic `if` around ~160 instructions of selects (it ran in every block, 10%): put the masked/unmasked block bodies in a `@cute.jit` helper with explicit args (closures capturing outer variables cannot be called inside staged for/if) instantiated twice. (8) `tm.set(ACCUMULATE, dynamic)` inside a jit helper leaks staged state -> rebuild the tiled MMA from the op inside the helper and zero-init accumulators (static accumulate=True). (9) `cutlass.range_constexpr` only works in @cute.jit/@cute.kernel functions. (10) An "empty" mbarrier that has no first producer must start at parity 1. (11) ncu `--page source --print-source cuda,sass --csv` + CUTE_DSL_LINEINFO=1 shows per-line exec counts and `@P` predication (handoff/scripts/common/src_an.py).

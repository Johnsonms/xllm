Full-step profiles (1 GPU, L=16384, torch.profiler + chrome-trace call-site attribution) taken 2026-10-23 after the CuTe AWM backward landed, extended 2026-10-24 with 8-GPU FSDP2 traces (user: "去看 FSDP overlap 的问题").

**gekko-0.9B B2 (1258 ms/step, cub TSDN, swift SCA):** swift SCA fwd+bwd 671 ms = 58% (materialized attention matrix ~105 GB); TSDN CUB ~120 ms; fp32 CE grad GEMM 64 ms (TF32 in train.py -> ~5); rope ~70; norms ~65; AWM cute ~10. **7.1B B1 (1150 ms):** GEMMs ~600 ms (54%), SCA 265, TSDN CUB 130. After cute SCA ([[xllm-cute-sca]]): 0.9B 590, 4B 455, 7.1B 968 ms on 1 GPU.

**8-GPU FSDP2 findings (2026-10-24, all cute backends):** (1) Communication IS overlapped on all presets: compute-stream gaps under NCCL <= 15 ms/step (only the first all-gather and the last reduce-scatter are exposed); bf16 reduce-scatter or reshard_after_forward=False change nothing (7.1B 1021 -> 1017/1019). (2) The multi-GPU "penalty" (7.1B 1031 vs 942 1-GPU, 4B 494 vs 444) is straggling: per-rank step time depends on the batch because the cute SCA skips blocks across segment boundaries (same seed: 4B steps 432-520 ms, SCA kernels 79 vs 155 ms; a batch without eos is the worst case); with identical batches on all ranks 7.1B = 960, 4B = 449. Not fixable in FSDP; needs faster worst-case SCA (bwd S=128 ~0.57 PFLOPS, fwd 1.2) or work-balanced batches. (3) BUG FIXED (commit 671884b): `create_on_gpu()` restored the default device with set_default_device("cpu") which leaves a DeviceContext TorchFunctionMode active for the whole run (24k python __torch_function__ calls per 4B forward): 4B 1-GPU 554 -> 444 ms, 0.9B 590 -> 530, 8-GPU 4B 614 -> 504. Affects train.py too (build_model uses it). (4) gekko-4B forward is still launch-bound (1 GPU: ~50 ms GPU idle/step; 8 GPUs ~60-80): triton causal conv 108 calls ~17 ms, F.linear 55 us/call, FSDP2 per-parameter python (~16 params/layer), TSDN/AWM/SCA wrappers 0.2-0.3 ms/call. New `ModelConf.fsdp_layers_per_group` (commit 1f9d3c0; layer 0 alone, then groups): 4B 8 GPUs 504 -> 485 at 4 (same-batch 449 -> 430), +1 GB; loss/gnorm parity to bf16 noise. SCA segment_starts/query_limits cached per segment_idx tensor.

**How to apply:** scripts in scratchpad `prof/` of session d3839bfb (also handoff/scripts/profile/): fsdp_trace.py (torchrun harness; env FSDP_FP32_RS, FSDP_RESHARD, SAME_SEED, SEED_OFFSET, PROF_STEP, WITH_STACK, TRACE_OUT, CFG_<field>), gaps.py (compute-stream gaps inside the FWDBWD window, NCCL overlap), gapattr.py (GPU-idle time by python frame; --ops variant by cpu_op), cpuself.py (CPU self time per python function in the forward), kcmp.py (kernel diff of two traces), run1.sh (env + torchrun wrapper). Pitfalls: `gpu_user_annotation` covers only the forward (backward runs on the autograd thread) -> put torch.cuda.synchronize() inside the record_function and use the CPU `user_annotation` as the window; the first profiled step carries profiler warm-up (+200 ms); world_size==1 FSDP2 takes a different per-param `.to()` path than world>1.
